# HILFU FC v8.7 — 쿼터별 점수 카드 터치 입력

- 웹앱 상단 **⚽ 경기 스코어**의 **1Q~5Q 카드 자체가 입력 버튼**입니다. 감독/승인 코치는 카드를 눌러 우리 팀과 상대 팀 득점을 한 화면에서 기록하고 **점수 저장**을 누릅니다.
- 로그인하지 않은 일반 선수는 카드와 전체 결과를 볼 수 있지만 수정 버튼은 비활성화됩니다.
- 이전 v8.6에서 라인업 아래에 있던 **현재 쿼터 득점** 패널은 제거해 중복 입력을 없앴습니다.
- **쿼터별 점수 자동 합산**과 **최종 점수 직접 입력** 두 모드는 유지됩니다. 모드를 바꾸더라도 기존 기록은 지워지지 않습니다.
- 기존 Firebase 자동 동기화, 승인 편집자 권한, 경기 이력, 최근 10개 백업·복원 기능과 데이터 경로는 그대로 유지됩니다.
- 점수가 없으면 **—**, 0득점은 **0**으로 표시하며 0~99 정수만 저장합니다.
- 이미 저장된 1Q~5Q 스코어 데이터는 그대로 가져와 표시합니다.
- 이번 변경에 필요한 Firebase 보안 규칙 수정은 없습니다.

## 확인 사항
- 익명 브라우저: 공식 점수판 표시, 변경 버튼 비활성화 확인.
- 감독/승인 코치: 상단 카드 터치 → 입력창 → 저장 완료 후 다른 기기 반영 확인이 필요합니다.

## v8.6 화면 및 입력 방식
- 전체 **경기 스코어**는 페이지 상단 독립 패널에서 항상 확인합니다.
- **쿼터별 점수 입력**은 **⚽ 라인업** 화면의 **⚽ 현재 쿼터 득점** 패널에 배치했습니다. 라인업에서 1Q~5Q를 바꾸면 점수 입력칸도 해당 쿼터로 변경됩니다.
- 전체 스코어 계산 방식은 **쿼터별 점수 자동 합산 / 최종 점수 직접 입력** 두 가지를 선택합니다. 수기 모드에서는 전체 점수판에서 별도로 최종 득점을 입력합니다.
- 어느 모드를 선택하든 쿼터별 점수와 수기 최종 점수는 **각각 보존**합니다. 현재 선택한 모드의 결과를 전체 스코어로 표시합니다.
- 미입력은 `—`, 무득점은 `0`으로 구분하며 정수 `0~99`만 허용합니다.
- 이전 v8.5의 선수·라인업·점수 기록·경기 이력·자동 백업·복원은 그대로 유지합니다. **새 경기 시작 시 두 방식 점수 모두 초기화**되지만, 보관된 이전 경기는 기존 점수를 유지합니다.
- 일반 방문자는 로그인 없이 점수와 이력 열람만 가능합니다. 감독·승인 코치 로그인 시 점수를 수정할 수 있습니다.
- 데이터 저장은 기존 `score` 필드를 사용하므로 **v8.4 Firebase Firestore 보안 규칙 수정이 필요 없습니다.**

## 검증 참고
- GitHub에서 v8.6 파일 확인 및 JS 문법 검사 완료.
- 실제 서비스에서 로그인 없는 점수판/라인업 열람과 잠긴 입력칸을 확인해야 합니다.
- 승인 편집자 계정의 실제 저장은 공식 데이터를 변경하므로 별도 테스트가 필요합니다.

## 이전 v8.5 기능 (유지)
- **쿼터별 입력:** 1Q부터 5Q까지 각 쿼터의 우리 팀/상대 팀 득점을 0~99골 범위에서 입력합니다. 입력된 점수는 자동 합산됩니다. 5개 쿼터를 모두 입력하면 최종 스코어로 표시하고, 일부만 입력했으면 진행 중 누적 점수로 표시합니다.
- **최종 점수만 입력:** 쿼터 기록 없이 최종 결과만 기록할 수 있습니다. 입력 방식을 바꿔도 서로 다른 모드의 기존 값은 지워지지 않습니다.
- **저장·열람:** 개인 보드에서는 개인 클라우드에, 공식 보드에서는 승인된 감독·코치가 수정 시 Firebase에 자동 저장됩니다. 일반 팀원은 로그인 없이 점수판을 볼 수 있습니다.
- **경기 이력 연계:** `새 경기`를 만들면 새 경기의 스코어는 비워지고, 보관된 이전 경기에는 당시 스코어가 남습니다. 자동 백업과 복원에도 점수가 포함됩니다.
- **호환성:** v8.4 이전에 점수가 없던 데이터는 미입력 상태로 표시합니다. 기존 선수, 라인업, 전술 데이터는 변경하지 않습니다.

## 배포 및 보안
- GitHub Pages의 `index.html`에 구현됐습니다. 캐시 갱신을 위해 v8.5 표시와 버전 쿼리 파라미터를 사용합니다.
- **Firestore 규칙은 v8.4에서 추가된 권한 설정 그대로 사용합니다. 이번 버전으로 인한 Firebase 규칙 변경은 없습니다.**
- 실제 로그인한 감독·코치가 점수를 입력한 뒤 다른 기기에서 저장·조회되는지는 운영 환경에서 별도 확인이 필요합니다.

## v8.4 기능
- **과거 경기 열람:** `지난 경기`에서 저장된 경기를 누구나 로그인 없이 읽기 전용으로 열람합니다. 공식 현재 경기로 언제든지 돌아올 수 있습니다.
- **새 경기:** 감독/승인 코치가 새 경기를 만들 때 **현재 공식 경기 데이터를 먼저 불변 이력으로 보관**합니다. 선수 기본 정보와 가능 포지션, 각 쿼터 포메이션은 유지하고 참석 체크, 5쿼터 배치, 전술 보드/메모를 초기화합니다. 데이터 보관과 공식 보드 갱신은 하나의 Firestore 트랜잭션으로 처리됩니다.
- **자동 백업:** 공식 팀 보드의 수정, 개인→공식 복사, 새 경기 시작, 복원 시 변경 **직전** 내용을 Firestore의 최근 10개 순환 슬롯에 저장합니다. 백업은 수정 권한 있는 사용자만 볼 수 있습니다.
- **복원:** 경기 이력 또는 최근 백업을 선택하여 기존 현재 공식 상태로 복원할 수 있습니다. 복원 전 현재 내용도 다시 자동 백업되며 2중 확인과 수정번호 충돌 검사를 거칩니다.
- **동기화 표시:** 비로그인 공개 보드의 상단 연결 표시가 `미연결`이라고 혼동을 주던 현상을 수정합니다.

## 데이터 저장 경로
- 현재 공식: `hilfuTeams/official` (기존 경로 유지)
- 개인: `hilfuStates/{uid}` (기존 경로 유지)
- 경기 이력: `hilfuMatchArchive/{archiveId}` (공개 조회, 승인 편집자만 생성, 불변 기록)
- 최근 백업: `hilfuTeamBackups/slot0`~`slot9` (감독·승인 코치만 접근)
- 코치 권한: `hilfuTeamAccess/official` (기존 권한 유지)

## 반드시 수행: Firebase 보안 규칙 게시

**GitHub의 `firestore.rules`를 바꿔도 Firebase 운영 서버의 규칙은 자동 갱신되지 않습니다.**

1. Firebase Console → Firestore Database → **규칙(Rules)** 메뉴를 엽니다.
2. 이미 Firebase 콘솔에 게시한 **기존 규칙 전체를 유지**합니다. 특히 실제 감독 UID를 `PASTE_OWNER_UID_HERE`로 되돌리지 마세요.
3. GitHub 저장소의 [firestore.rules](https://github.com/skyfiow1-collab/hilfu-fc/blob/main/firestore.rules)에서 `match /hilfuMatchArchive/{matchId}`와 `match /hilfuTeamBackups/{backupId}` 두 블록을 복사하여 마지막 `match /{document=**}` **앞에 추가**합니다.
4. `hilfuTeams/{teamId}`의 `allow get: if teamId == 'official';` (v8.3 공개 조회 규칙) 및 기존 수정·권한 체크는 그대로 유지합니다.
5. Firebase Console의 **게시(Publish)**를 누릅니다. 게시하지 않으면 새 경기 보관/백업/복원/과거 경기 조회에 `permission-denied`가 발생할 수 있습니다.

## 운영 권장 사항
- 첫 새 경기 시작 전 감독이 공식 데이터 JSON 백업을 한 번 수동 다운로드해 두세요.
- 새 경기 생성은 이전 경기 이력을 영구 보존하지만 자동 백업은 최근 **10번의 공식 보드 수정 이전 상태**만 보관합니다. 오래된 백업을 보존하려면 JSON 파일로 다운로드해 두세요.
- 첫 배포 후 감독 로그인 → 지난 경기 목록 확인 → 새 경기 테스트 → 보관된 경기 열람 → 복원까지 순서대로 확인합니다.
- 기존 Firebase 문서나 선수 데이터는 마이그레이션 또는 초기화하지 않습니다.
- Firestore 데이터가 공개되는 경로는 공식 팀 보드와 **경기 이력 전체**입니다. 개인 보드 및 최근 백업은 공개되지 않습니다.

## 주의
기존 공식 보드의 경기 날짜/이름 필드는 처음에는 없을 수 있습니다. 첫 `새 경기`에서 보관 이름을 직접 입력하면 됩니다. 이전 경기로 돌아가려면 `현재 경기로`를 선택합니다. 다른 편집자가 변경한 경우 트랜잭션에서 안전하게 중단하며 강제 덮어쓰지 않습니다.
